# Release review: 2026-10-22

Scope: first-party app boundaries, Games rules/rendering/input, SD/Voice failure
contracts, Companion runtime packaging, current documentation, CI and release
publication. This is a focused engineering review, not an exhaustive security
or electrical certification. GPS changes and vendor rewrites are excluded.

## Optimizations

- A bounded grid DDA replaces incremental wall marching in DOOM LITE.
- One existing 8-bit framebuffer changes dimensions; no second screen buffer.
- The initial screen buffer is allocated at its final 8-bit depth.
- Rules have no display or ESP-IDF dependency; core tests run on the host.
- Loopback HTTP tests use an isolated backup directory, validate SD readiness,
  reject untrusted host/token requests and leave physical devices untouched.
- Companion source kits have deterministic member metadata and checksums;
  they contain no configured app, interpreter paths or personal files.
- Sprite drawing uses a small per-frame depth buffer and generated geometry;
  no WAD, external asset loading or new runtime dependencies.

## Retained safeguards and open work

Content hashes and index-last SD publication, retained recovery payloads,
non-destructive Voice mount failure, verified offload and serialized storage
remain covered by existing checks. Three known four-byte MP3 source files must
be replaced by their owner; ordinary sync intentionally rejects invalid input.
Automatic recovery-folder pruning and a hash cache are deferred: neither should
weaken recovery or use timestamps as a substitute for integrity.

Physical rc3 display/input, Voice Wi-Fi/ASR, power-cut recovery and endurance
remain open. Earlier Music/Reader reports are historical observations, not rc3
acceptance. GPS is paused after a zero-byte UART result. The broken old SD was
physically damaged in a reader; it is not evidence of a firmware storage fault.

## Publication proof

Host checks, sanitizer run, renderer fixtures, firmware build/size, package
checksums, CI commit and public release asset availability must be reported
separately. See RELEASE_0.3.0-rc3.md and HARDWARE_ACCEPTANCE.md. A GitHub
pre-release does not imply stable or M5Burner acceptance.
