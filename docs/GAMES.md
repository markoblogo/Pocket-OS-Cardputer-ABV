# Games

Open Launcher > GAMES. Up/Down selects a game; Enter starts it. Go or Escape
returns to Games; a second Go returns to Launcher. R starts a new game.
Games use the shared framebuffer and do not write SD or internal Voice storage.

## Tetris

Rotate the device **clockwise** into portrait. The display becomes 135x240 and
returns to landscape on leaving Tetris, including after game over.

Arrow directions are remapped to their physical direction after rotation:

| Key before turning the device | Action in portrait |
| --- | --- |
| Up | Move right |
| Down | Move left |
| Left | Rotate |
| Right | Soft drop |
| Enter | Hard drop |
| P or Space | Pause / resume |
| R | New game |
| Go / Escape | Games menu |

Holding an arrow repeats after 280 ms, then every 90 ms. The same keyboard keys
still act as the familiar visual arrows after turning the device. Pieces use a
shuffled seven-piece bag, a next-piece preview, a ghost landing outline and
small horizontal rotation kicks. The O piece rotates in place. Completed lines
score 100/300/500/800 times the current level; hard drops score two per row.

The renderer uses one 32,400-pixel, 8-bit framebuffer in either orientation.
Switching orientation releases the old buffer before allocating its replacement.

## Klondike

Draw-one rules. Clubs/spades are black; diamonds/hearts are red.

1. Use Left/Right to choose a pile. In the tableau, Up/Down chooses a face-up
   card within its column. Up from the first face-up card reaches the upper row;
   Down from that row returns to a tableau column.
2. Enter selects the card and the valid descending, alternating-colour run below
   it. Move the cursor to the destination and press Enter again.
3. An empty tableau accepts a King-led run. A foundation accepts only one card,
   in suit order from Ace to King. Exposed hidden cards turn over automatically.
4. Enter on the stock draws one card. After it empties, Enter recycles the waste
   in the original order. Enter on the selected source cancels the selection.
5. Fill all four foundations to win; Enter then deals again. R redeals at any time.

Each column shows a six-card window. The column caption is `column:hidden-above`;
Up scrolls back to earlier playable cards. Yellow marks the focused card and
selected source. Invalid destinations leave the selection available to retry.
There is no undo or automatic solve.

## DOOM LITE

An original raycast adaptation; no DOOM engine, WAD, borrowed sprites or music.
The graphics and enemy sprite are generated by this project.

- Up/Down moves; Left/Right turns. Hold arrows for continuous steps.
- Enter fires with a cooldown. Only a visible target in the crosshair takes
  damage. Walls block shots; each enemy takes two hits.
- Enemies approach in line of sight and attack only when close. Health does not
  decrease just because time passes. The minimap shows walls, enemies and player.
- Eliminate three enemies, then reach the southeast exit, marked on the minimap.
- Enter after winning or dying restarts; R restarts at any time; Go leaves.

## Verification boundary

Host tests cover bag/rotation/line clearing, pause and timer rollover, Klondike
suits/runs/foundations/recycling/card conservation, Doom spawn/collision/shots/
line of sight/cooldown/damage/win conditions, plus 9,999 mixed input steps.
Renderer checks exercise landscape/portrait layouts and caption bounds with a
host drawing adapter. Its font metrics are approximate. Hardware orientation,
held-key behavior, colours and frame pacing remain a device acceptance task in
HARDWARE_ACCEPTANCE.md. Preview images are software fixtures, not hardware proof.
